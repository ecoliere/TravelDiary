# TravelDiary

Android-приложение, которое ведёт дневник путешествий автоматически.

Обычно чтобы сохранить память о поездке, приходится вручную разбирать фото, вспоминать, где и когда что было снято, и как-то это оформлять. TravelDiary берёт эту работу на себя: после включения отслеживания приложение само определяет места остановок, подбирает подходящие фото из галереи и пишет к ним описание.

# Возможности
фоновое отслеживание перемещений с минимальным расходом батареи
автоматическое определение остановок — движение отделяется от реальной остановки на месте
поиск фото, снятых рядом по месту и времени, и выбор из них лучшего
автогенерация текстового описания остановки с учётом времени суток, типа места и сезона
архив в виде календаря — дни с записями выделены визуально
быстрый экспорт записи через системное меню «Поделиться» и расширенный экспорт с выбором формата
Как это устроено

Работа приложения строится в три шага: сбор данных → обработка → просмотр.

Сбор данных выполняет LocationTrackingService — фоновый сервис, который получает координаты через Fused Location Provider. Когда фиксируется остановка длительностью больше порогового значения, в работу включается StopDetector. Далее GalleryScanner находит фотографии, сделанные в это время и в этом месте, PhotoAnalyzerAdapter выбирает из них лучшую, а CaptionGenerator формирует текстовое описание по шаблону.

Определение остановок. Используется адаптированный алгоритм DBSCAN: точки группируются не только по расстоянию (вычисляется по формуле гаверсинусов для сферических координат), но и с учётом времени — кластер признаётся остановкой только при разнице между первой и последней точкой не менее 3 минут. Это позволяет отделить GPS-шум на месте от реальной остановки.

Выбор фотографии. Для каждого снимка, попавшего в интервал остановки, рассчитывается суммарная оценка: часть баллов начисляется за техническое качество (разрешение, размер файла, EXIF-данные), часть — за соответствие контексту остановки по времени и расстоянию. Выбирается снимок с максимальной суммарной оценкой.

# Архитектура

Приложение построено по паттерну MVVM и разделено на три модуля:

app — экраны, сервисы, база данных
stop-detector — логика определения остановок (DBSCAN)
photo-analyzer — анализ фотографий и генерация описаний

Данные хранятся локально через Room (SQLite), обновление интерфейса реализовано через LiveData/Flow, фоновые операции выполняются на корутинах.

Ключевые экраны: MainActivity (запуск/остановка отслеживания), CalendarActivity (архив по дням), DayEntriesActivity (список остановок за день), StopDetailActivity (детали записи и экспорт).

# Стек

Kotlin 1.9.22, Android SDK 34 (минимум 26), Jetpack (ViewModel, LiveData) 2.7.0, Room 2.6.1, Coroutines/Flow 1.7.3, Google Play Services Location 21.1.0, ExifInterface 1.3.7, Glide 4.16.0, Material Components 1.11.0, Gradle 8.2 / AGP 8.2.2.

# Установка

Есть готовый apk. Файл устанавливается стандартным способом — при первом запуске потребуется разрешить доступ к геолокации и медиатеке, без них отслеживание и поиск фото работать не будут.

Проект открывается в Android Studio, после синхронизации Gradle запускается на устройстве или эмуляторе с Android 8.0 (API 26) и выше.

# База данных

Основная сущность — TravelEntry:

Поле	Тип	Описание
id	Long	Уникальный идентификатор записи
latitude, longitude	Double	Координаты центра остановки
address	String	Адрес места, полученный геокодированием
startTime, endTime	Long	Временные метки начала и окончания остановки
photoPath	String	Путь к выбранной фотографии
caption	String	Текстовое описание остановки
